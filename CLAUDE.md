# WPR Adoptable Pets Widget

An automated data pipeline and frontend widget that scrapes adoptable pet listings from five central Wisconsin shelters and presents them in a single, branded Wausau Pilot & Review interface. The widget runs as a static HTML page deployed to GitHub Pages and embedded in WordPress via iframe.

**Repository:** `RowanFlynnPilot/wpr-adopt-widget`
**Live URL:** `https://rowanflynnpilot.github.io/wpr-adopt-widget/adopt-widget.html`
**Data endpoint:** `https://rowanflynnpilot.github.io/wpr-adopt-widget/pet-data.json`

## File Map

| File | Purpose |
|---|---|
| `build-widget-data.js` | **Main scraper.** Orchestrates all five shelter scrapers, normalizes data, deduplicates, outputs `pet-data.json`, and injects data into the widget HTML. ~838 lines. |
| `adopt-widget.html` | **Frontend widget.** Self-contained HTML/CSS/JS. Has hardcoded fallback data + live fetch from GitHub Pages JSON. ~603 lines. Also copied to `docs/`. |
| `scrape-lincoln.js` | **Legacy scraper** for Lincoln County via furrypets.com (dynamic WordPress site). Lincoln is now scraped via Adoptapet in the main builder; this file is retained as a fallback reference. |
| `pet-data.json` | **Output data.** Generated by the scraper. Contains `lastUpdated`, a `shelters` object keyed by shelter slug, `scrape_status` per shelter, and a `firstSeen` url→ISO-date map (null = pet predates tracking) that powers "New" badges and the longest-waiting spotlight. |
| `package.json` | Dependencies: `puppeteer ^23.0.0`. Scripts: `build-widget-data`, `scrape:lincoln`, `scrape:all`. |
| `.github/workflows/scrape.yml` | GitHub Actions workflow. Runs twice daily (8 AM / 8 PM Central) or on manual dispatch. Installs Chrome, runs scraper, commits + pushes results, then runs a health gate that fails the run (and auto-opens a GitHub issue) if any shelter scrape failed. |
| `check-scrape-health.js` | CI health gate. Reads `scrape_status` from `pet-data.json`; exits non-zero on any `failed` or `stale` shelter so outages can't go unnoticed. |
| `build-featured-pet.js` | **Newsletter snapshot generator.** Picks one long-stay pet from `pet-data.json` and renders a branded ~600px card to PNG (rendered @2×) for embedding in the daily email newsletters. Handles rotation/dedup and writes `featured-history.json` + a metadata sidecar. |
| `featured-history.json` | Rotation/dedup log for the featured-pet snapshot: `url → [ISO timestamps featured]`. Enforces "≤3 features per 14 days" and "different pet each edition". Pruned to 90 days. |
| `docs/snapshots/` | Newsletter PNGs: `featured-pet-latest.png` (always newest), `featured-pet-YYYY-MM-DD-{am,pm}.png` (stable per-edition archive), and `featured-pet.json` (who's featured + metadata). |
| `docs/` | GitHub Pages deploy directory. Contains the widget HTML, pet-data.json, update-log.txt, and diagnostic HTML snapshots. |
| `docs/diag-*.html` | Diagnostic page snapshots saved by scrapers when results are unexpectedly low or a fallback fires. Useful for debugging anti-bot blocks or site layout changes. |

## Shelters & Scraper Details

### 1. Marathon County Humane Society (`marathon`)
- **Source:** Adoptapet.com shelter page
- **Shelter ID:** `77626-humane-society-of-marathon-county-wausau-wisconsin`
- **Method:** `scrapeAdoptapet()` — Puppeteer with client-side pagination (clicks Next/numbered buttons; URL `?page=N` doesn't work)
- **Fallback:** If card scraping finds ≤3 pets, a raw HTML fallback extracts pet URLs from the page source (RSC payloads, script data)

### 2. Clark County Humane Society (`clark`)
- **Source:** Petfinder — official API when `PETFINDER_API_KEY`/`PETFINDER_API_SECRET` env vars (GitHub Actions secrets) are set (`fetchPetfinderApi('WI34')`, free key at petfinder.com/developers); otherwise falls back to HTML scraping the member page
- **Slug:** `neillsville/clark-county-humane-society-wi34`
- **Scrape method:** `scrapePetfinder()` — Scrapes `a[href*="/details/"]` cards, parses alt text for name/breed/age/gender
- **Note:** API descriptions are truncated by Petfinder (~250 chars); the HTML scraper gets full bios

### 3. Adams County Humane Society (`adams`)
- **Source:** Adoptapet.com shelter page
- **Shelter ID:** `76343-adams-county-humane-society-friendship-wisconsin`
- **Method:** `scrapeAdoptapet()` (same as Marathon)

### 4. Lincoln County Humane Society (`lincoln`)
- **Source:** Adoptapet.com shelter page (migrated from furrypets.com which was unreliable)
- **Shelter ID:** `66070-lincoln-county-humane-society-merrill-wisconsin`
- **Method:** `scrapeAdoptapet()` (same as Marathon/Adams)
- **Note:** `scrapeLincoln()` function still exists in the codebase for the old furrypets.com approach but is not called from `main()`

### 5. New Life Pet Adoption Center (`nlpac`)
- **Source:** nlpac.com/pets (direct HTML)
- **Method:** `scrapeNlpac()` — Two-pass: first scrapes listing page for pet links (`a[href*="/q/pets/"]`), then visits each detail page to extract name, species, breed, age, bio, and photo
- **Species detection:** Parses "Animal Type" field from structured `<li>` data on detail pages

### Cross-Shelter Deduplication
After all scrapers run, `main()` deduplicates by URL across shelters. Priority order: marathon → clark → adams → lincoln → nlpac (first occurrence wins). This handles Adoptapet cross-listing the same pet under multiple nearby shelters.

## Scraper Internals

### Anti-Bot Measures
All scrapers use a shared `makePage(browser)` helper that applies:
- Realistic Chrome User-Agent string
- `navigator.webdriver = false`
- Fake plugins array and language list
- `window.chrome.runtime` stub
- 1280×900 viewport

### Adoptapet Scraper (`scrapeAdoptapet`)
This is the most complex scraper (~270 lines). Key behaviors:
- **Pagination:** Client-side only. Detects "X - Y of Z" text to determine total count, finds and clicks numbered page buttons or "Next" links, waits for range indicator to update before scraping next page.
- **Card parsing:** Finds `a[href*="/pet/"]` links. Extracts name from `img[alt^="Photo of"]` or first text line (with cleanup for concatenated blobs like "AdaDomestic ShorthairFemale, 11 mos"). Breed extracted from second text line or parsed from fullText.
- **Bio fetching:** After card scraping, visits each pet's detail page to extract bio text (from `<p>` elements in main/article/content containers) and breed (from `<dt>Breed</dt><dd>` pairs, page title, or og:description meta).
- **Fallback:** If only ≤3 pets found from cards, re-fetches the page and regex-extracts `/pet/(\d+)-([a-z-]+)` URLs from raw HTML (catches server-rendered data that JS hydration may have removed).
- **Image optimization:** Rewrites Adoptapet image URLs to use their Cloudinary CDN with `w_400,ar_4:3,dpr_2` parameters.

### Data Normalization
All scrapers output a standard pet object:
```json
{
  "name": "Sonny",
  "species": "Dog",       // "Dog", "Cat", or "Other"
  "breed": "Schnauzer (Miniature)",
  "age": "3 yrs",
  "gender": "Male",
  "bio": "Short description...",
  "photo": "https://...",  // null if unavailable
  "url": "https://..."     // link to pet's detail page
}
```

Species classification uses keyword matching: cat breeds (shorthair, longhair, siamese, etc.) and URL patterns (`-cat$`) → Cat; small animals (rabbit, guinea pig, hamster, etc.) → Other; everything else → Dog.

## Frontend Widget

### Tech Stack
- **Single-file HTML** — all CSS and JS inline, no build step
- **Fonts:** Playfair Display (headings), Source Sans 3 (body) via Google Fonts
- **No frameworks** — vanilla JS with DOM manipulation

### WPR Brand Tokens
```css
--teal: #4a9e8e;
--teal-dark: #3a7d70;
--teal-light: #5fb8a6;
--teal-bg: #e8f4f1;
--ink: #1a1a1a;
--warm-white: #fafaf8;
--sand: #f2efea;
```

### Data Loading Strategy
1. Widget starts with **hardcoded fallback data** (`FALLBACK_DATA` const) so it always renders immediately
2. `loadLiveData()` fetches `pet-data.json` from GitHub Pages in the background (cache-busted with `?t=Date.now()`)
3. Merges live data per-shelter: if a shelter has live pets, replaces fallback; if empty, keeps fallback
4. Re-renders after merge

### Filters
- **Shelter filter:** All Shelters, Marathon County, Clark County, Adams County, Lincoln County, New Life PAC
- **Animal type filter:** All Animals, Dogs, Cats, Other (Other button auto-hides when no small animals exist)
- State tracked in `activeShelter` and `activeAnimal` globals; `render()` rebuilds all DOM

### Pet Cards
- Photo with smart cropping (`smartPosition()` — canvas-based edge detection to find focal third of image for `object-position`)
- Fallback emoji placeholder when no photo available
- Name, breed + age, bio excerpt, species/gender tags
- Click anywhere on card → opens pet detail modal
- Share button with Facebook, "Instagram & more" (native share sheet via Web Share API — shown only where `navigator.share` exists; attaches the pet photo when file-sharing is supported), email, SMS, and copy-link options
- "✨ New" badge when `pet.firstSeen` is within 8 days
- "Waiting the longest for a home" spotlight strip (top of unfiltered view): 3 oldest pets by `firstSeen`, falling back to lowest Adoptapet IDs until 3+ pets have tracked dates

### Widget Sections (per shelter)
- Branded header with shelter icon, name, location, and "Visit Website →" link
- Pet grid (responsive CSS grid)
- "View all at [shelter]" link at bottom
- Status banner showing total count + active filters

## GitHub Actions Pipeline

**Workflow:** `.github/workflows/scrape.yml`
**Schedule:** Twice daily — 13:00 UTC and 01:00 UTC (~8 AM / 8 PM Central) + manual dispatch
**Runner:** `ubuntu-latest` (60-min timeout, `scrape-pets` concurrency group prevents overlapping runs)

Steps:
1. Checkout repo
2. `npm install`
3. `npx puppeteer browsers install chrome`
4. `node build-widget-data.js` — runs all scrapers, outputs `pet-data.json` and refreshes `FALLBACK_DATA`/`FALLBACK_META` in `adopt-widget.html`
5. Copies `pet-data.json` + widget + logos to `docs/`, writes timestamp to `docs/update-log.txt`
6. Git commit + `pull --rebase` + push to `main` (no force push)
7. `node check-scrape-health.js` — fails the run if any shelter's `scrape_status` is `failed` or `stale`
8. On failure, auto-opens a GitHub issue (skipped if an open "Pet scraper failure" issue already exists)

**Bot identity:** "WPR Pet Bot" / bot@wausaupilotandreview.com

**GitHub Pages:** Serves from `main` branch `/docs` directory.

## Featured Pet Newsletter Snapshot

**Workflow:** `.github/workflows/snapshot.yml` — runs twice daily (11:00 UTC = 6 AM CT, 21:00 UTC = 4 PM CT) so the morning and afternoon email newsletters feature different animals. Reads the committed `pet-data.json` (no re-scrape) and renders a PNG via Puppeteer.

**Why a PNG:** email clients (Gmail/Outlook/Apple Mail) strip iframes and JS, so the live widget can't embed. The newsletter `<img>`-embeds a hosted PNG instead. Mirrors the sibling `wpr-woodchucks-widget` snapshot pattern.

**Selection** (`rankCandidates` in `build-featured-pet.js`):
- Goal is to spotlight pets listed the longest (the "≥ 2 months" focus). Tenure uses the best signal per pet: tracked `firstSeen` date → Petfinder `publishedAt` → else the pet predates `firstSeen` tracking (began 2026-06-13) and is treated as a long-stay "veteran", ranked oldest-first by Adoptapet listing ID.
- Tiers: (1) provably ≥ 60 days, (2) pre-tracking veterans, (3) tracked but younger. Until `firstSeen` matures past 60 days (~mid-Aug 2026), tier 1 is empty and the veterans carry the focus.
- Rotation rules: never feature a pet more than 3× in a rolling 14 days; never repeat the immediately-previous edition's pet. Chosen pet must have a photo and pass a tolerant liveness check (only a definitive 404/410 rejects it).

**Embedding in the newsletter** (note: GitHub Pages serves from `docs/`, so `docs/` is stripped from the public URL): use the per-edition URL for a stable image that won't change after send — `https://rowanflynnpilot.github.io/wpr-adopt-widget/snapshots/featured-pet-YYYY-MM-DD-am.png` (or `-pm`). `https://rowanflynnpilot.github.io/wpr-adopt-widget/snapshots/featured-pet-latest.png` always shows the newest. `snapshots/featured-pet.json` exposes the featured pet's name/shelter/URL if the newsletter system wants to wrap the image in a link to the adoption page.

**Local run:** `PUPPETEER_EXECUTABLE_PATH="C:\Program Files\Google\Chrome\Application\chrome.exe" node build-featured-pet.js` (the env var points Puppeteer at system Chrome; CI installs its own).

## Common Maintenance Tasks

### A scraper returns 0 pets
1. Check `docs/diag-{shelter}-*.html` diagnostic files — open in a browser to see what the page actually returned
2. Common causes: anti-bot block (Cloudflare challenge page), site layout change (selectors no longer match), pagination change
3. The Adoptapet scraper has a fallback path for low results — check if it fired in the Actions log
4. When a scrape returns 0, `main()` carries forward the previous run's pets for that shelter (marked `status: "stale"` with `staleSince` in `scrape_status`) for up to 14 days, so the widget keeps showing real, recent pets. After 14 days the shelter goes to `failed`/empty. The widget shows a yellow stale notice for `stale` shelters and an honest "having trouble reaching this shelter" empty state for `failed` ones.

### Adding a new shelter
1. Write a scraper function in `build-widget-data.js` (use `scrapeAdoptapet()` for aggregator sites, `scrapeNlpac()` for direct HTML sites, or `scrapePetfinder()` for Petfinder)
2. Call it from `main()` and assign to `data.shelters.{key}`
3. Add the shelter key to the `shelterOrder` dedup array
4. In `adopt-widget.html`:
   - Add entry to `SHELTERS` config object
   - Add filter button in `#shelterFilter`
   - Add fallback data in `FALLBACK_DATA`
   - Add footer link
5. Test locally: `node build-widget-data.js` then open `adopt-widget.html`

### Updating fallback data
`FALLBACK_DATA` (pet listings) and `FALLBACK_META` (lastUpdated + scrape_status) in `adopt-widget.html` are **auto-refreshed by every build**: `injectIntoWidget()` in `build-widget-data.js` replaces the content between the `/*FALLBACK_DATA_START*/.../*FALLBACK_DATA_END*/` and `/*FALLBACK_META_START*/.../*FALLBACK_META_END*/` comment markers. Never hand-edit the JSON between the markers (it gets overwritten); never remove the markers (injection logs a ⚠️ warning and skips if they're missing). The fallback is therefore never older than the last successful Actions run.

### Image URLs
- **Adoptapet:** Uses Cloudinary CDN. Template: `https://media.adoptapet.com/image/upload/c_auto,g_auto,w_400,ar_4:3,dpr_2/f_auto,q_auto/{petId}`
- **Petfinder:** Uses CloudFront. Template: `https://dbw3zep4prcju.cloudfront.net/animal/{animalId}/image/{imageId}.jpg`
- **NLPAC:** Direct URLs from `custompages` path on their site

### Key Debugging Tips
- The scraper saves diagnostic HTML snapshots to `docs/diag-{shelter}-{context}.html` whenever results are unexpectedly low. Open these in a browser to see exactly what Puppeteer received.
- Adoptapet is a Next.js React app — after JS hydration, pet cards may be re-rendered differently than the server HTML. The fallback path in `scrapeAdoptapet` handles this by extracting URLs from raw page source.
- Petfinder and NLPAC may return bot-detection pages. The `makePage()` stealth settings help but aren't foolproof. If a scraper consistently returns 0, the site may have tightened anti-bot measures.
- The fallback injection in `adopt-widget.html` is marker-based: `injectIntoWidget()` replaces the `/*FALLBACK_DATA_START*/…END*/` and `/*FALLBACK_META_START*/…END*/` blocks. If a marker is missing it logs `⚠️ … markers not found` and skips the write — grep the Actions log for that warning if the widget seems to ship stale fallback data.
- Species classification lives in `classifySpecies(breed, url)` and deliberately ignores the pet's name and free-text details — a Pit Bull named "Finch" must not be classified as a bird. Keep it that way when touching it.
